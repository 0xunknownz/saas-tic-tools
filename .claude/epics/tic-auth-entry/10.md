## What to build

按已确认的忘记密码页方案 1，实现 TIC 工具箱双栏忘记密码页。复用登录页的双栏布局：桌面左侧约 42% 为浅蓝品牌介绍区，右侧白色区域居中展示紧凑表单，不另加包围表单的卡片。

左侧沿用 TIC工具箱品牌、“检验检测工作，从这里开始。”、“连接项目、标准与报告，让团队工作井然有序。”及项目协作、标准查阅、报告归档三项介绍。右侧依次展示标题“找回密码”、说明“输入账号邮箱，我们会向你发送密码重置链接。”、标签“邮箱”、占位文字“请输入工作邮箱”、主按钮“发送重置链接”、链接“返回登录”及辅助提示“如未收到邮件，请检查垃圾邮件文件夹。”。移动端收拢品牌介绍，优先展示表单。

复用现有 Foundation Tenant UI 密码重置申请能力与真实接口；保留发送中、成功、校验失败和请求失败状态。成功提示统一使用“如果该邮箱对应一个账号，重置链接已发送。请查收邮件。”，不得暴露账号是否存在，不将请求成功描述为邮件已送达。

遵循 TIC 设计规范：背景 #F8FAFC、白色面板、主色 #3B82F6、文字 #0F172A / #475569 / #64748B、边框 #E2E8F0；中文系统字体，标题 19px/800、正文 13px、控件 12px，面板/输入/按钮圆角分别为 16/12/9px。不新增后台接口、数据库结构、验证码输入、重发倒计时或注册入口；本任务不扩展设置新密码页面。

## Acceptance criteria

- [x] 桌面符合已选忘记密码页方案 1，复用登录页双栏布局和品牌介绍，颜色、字体、圆角符合 TIC 规范。
- [x] 登录页的忘记密码入口可到达此页，此页可返回现有登录页；直接访问和刷新页面正常。
- [x] 邮箱经过既有校验后提交真实密码重置申请接口；必填或格式错误可理解，并与输入字段关联。
- [x] 请求期间显示发送中并防止重复提交；失败时显示可理解的错误，保留邮箱并允许重试。
- [x] 成功后显示统一的条件式提示，不区分邮箱是否存在、不声称邮件已送达；保留返回登录入口。
- [x] 复用原有密码重置协议，不破坏既有邮件链接与后续重置流程，不用假成功替代真实请求。
- [x] 小屏无页面横向溢出；邮箱标签明确，键盘可完成输入、提交和返回登录，焦点清晰，错误与状态反馈可被辅助技术识别。
- [x] 完成桌面、移动端视觉检查，通过类型检查及相关密码重置申请、登录入口回归测试，覆盖校验、提交中、成功、失败重试和返回登录。
- [x] 样式限定于本任务页面及复用布局，不影响其他认证页或管理端。
