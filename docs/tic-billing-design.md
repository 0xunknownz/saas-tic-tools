# TIC 租户账单管理规范（#13）

本页属于租户管理端，复用 #12 的 TenantLayout、导航和 TIC 样式；不修改 Web 认证页或平台管理端。标题“账单管理”，说明“管理当前订阅与套餐。”。布局尺寸、颜色、字体和圆角继承 [成员管理规范](tic-members-design.md)。

## 订阅摘要

使用公开 useBilling，保持现有 API、并行目录/订阅读取与服务端刷新。摘要横向展示套餐、真实状态、快照金额/币种/周期与 UTC 有效期；窄屏转两列。金额沿用项目 currency + (amountCents / 100).toFixed(2)，不另建金额计算抽象。套餐名称只用 code 对应目录作显示回退；完整订阅状态仍取 status、cancelAtPeriodEnd 与 periodEnd。

无订阅显示说明；缺失期限显示未提供。active、past_due、pending、canceled、expired 分别标注，只有 active/past_due 套餐行高亮为当前套餐；pending 标为待支付，不误称已生效。未知期限不承诺额外可用时间。

允许取消的状态沿用 Foundation 协议：pending / active / past_due 且未安排取消。确认对话框解释待支付取消即终止、已付周期到期取消；取消进行中防重复，失败保留错误，成功后重新请求订阅，不按按钮结果伪造新状态。取消完成但刷新失败时，只显示读取错误与重试，避免展示过时摘要。

## 套餐表与购买

列为套餐、功能与额度、月付、年付。features、limits、prices 均来自响应，不翻译或猜测未定义额度含义，不硬编码示例金额。只展示接口有价格的周期和币种；缺失价格显示未提供，不合成年付折扣或默认货币。每个购买按钮与同格的价格相邻，提交 planCode、interval、currency 原始字段。

购买与取消共用同步锁，hook 的进行中状态禁用相关操作；失败可重试。成功仅称购买请求已受理，不宣称已支付。Foundation 0.2.1 Checkout 返回订阅 ID、提供方、reference、整数分与币种，不含跳转 URL；沿用 useBilling 的购买后刷新，不把 reference 当成 URL，也不增加支付跳转协议。

provider=none 明确提示并禁用购买；现有允许的取消仍可用。读取有加载、错误及重试，无套餐有空状态。套餐表为可聚焦的命名横向滚动区域，390px 下页面不横向溢出，价格和操作保持同格对应。

没有新增发票、流水、支付方式、折扣、用量图表、后端接口或数据库结构。专用验收数据仅在测试租户与独立测试夹具中使用，验收后清理。
