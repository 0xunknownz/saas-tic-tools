# TIC 租户成员管理规范（#12）

本任务将 TIC 工作台规范扩展至租户管理端。范围仅为 apps/tenant-admin；平台管理端与 Web 认证页不变。管理端仍使用真实 Foundation Tenant API，不使用工作台的示例数据。

## 布局与样式

复用 TenantLayout：桌面 72px 一级栏、232px 二级栏、58px 顶栏，内容内边距 16px 22px 28px。二级导航包含成员管理、账单管理与返回工作台。管理路由使用 TanStack Router，跨应用入口使用同域完整导航。

采用方案 3「轻量设置」：背景 #F8FAFC，白色面板，主色 #3B82F6，文字 #0F172A / #475569 / #64748B，边框 #E2E8F0。中文系统字体，标题 19px/800，面板标题 15px/800，正文与表格 13px，控件 12px；面板、输入、导航、按钮圆角 16/12/10/9px。所有产品样式以 .tic-admin 为作用域，样式入口仅由租户管理端加载。

小于 1000px，一级栏成为横向导航，二级栏由“管理菜单”展开；390px 下页面不横向滚动，成员表格在可聚焦的命名区域内独立横向滚动。桌面邀请侧栏 360px，窄屏不超过视口；原生 dialog 提供模态背景、焦点进入、Tab 约束、Escape 和关闭后的焦点恢复。

## 成员与操作

页面标题“成员管理”，说明“管理成员访问权限与账号安全。”。表格列为成员、邮箱、角色、MFA、加入时间、操作；显示当前账号、转发邀请标记，时间转换为 UTC 并明确标注。缺失时间/MFA 数据显示未提供，不推断事实。

复用公开 useMembers / useSession。成员管理权限沿用 tenant_admin 或 tenant.members.manage；角色调整另外检查 tenant.roles.manage。当前账号不显示自身安全操作。角色仅 tenant_admin / member；只提供其他管理员降级为普通成员，不新增提升能力；服务端保留最后管理员保护。

“管理”采用原生 details/summary 与按钮：Enter/Space 展开、Tab 进入操作、Escape 收起并恢复 summary 焦点。MFA 重置、密码重置、移除、角色降级均有明确对象和风险确认。凭据操作要求 trim 后非空原因；取消不提交，提交中禁重复并保留失败输入，成功调用 hook 的 refresh 读取真实状态。网络错误复用 Foundation 消息目录与请求关联 ID。

## 邀请与敏感结果

邮箱 trim 后验证必填及基本邮箱格式，错误通过 aria-describedby 与 aria-invalid 关联字段。邮件与手动邀请分别调用现有方法，统一提交锁防止交叉重复。失败保留输入可重试；受理不等于邮件送达。

每次打开侧栏挂载独立 useMembers(false)，关闭即销毁临时邀请凭据；重新打开空白且不暴露前次凭据。重置凭据在当前页可显式隐藏。凭据不写 localStorage/sessionStorage、日志或 URL。请求进行中等待响应再关闭，避免不明结果期间再次提交。

会话六态守卫、登录/选租户返回参数及无权限保护沿用现有逻辑；列表有加载、错误重试与空结果。未增加搜索、筛选、分页、接口或数据库结构。
